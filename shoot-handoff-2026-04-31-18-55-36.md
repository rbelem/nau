## Architecture

All code in `src/`:
- `main.rs` — entry point, wires CLI → lua eval → snap build
- `cli.rs` — clap derive, `shoot build [--file] [--stage] [--output] [--arch] <OUTPUT>`
- `lib.rs` — module exports
- `lua.rs` — mlua eval, injects DSL globals, configures `package.path` for `require`
- `dsl/init.lua` — injected Lua globals: `snap()`, `app()`, `merge()`
- `snap.rs` — `SnapMeta`/`SnapApp` structs, YAML serialization, `build_snap()`, `run_build()`, bubblewrap sandbox

## Build Pipeline Flow

1. CLI parses args
2. `evaluate_file()` reads shoot.lua, injects DSL globals, evals → `HashMap<String, SnapMeta>`
3. For each output: resolve archs, for each arch:
   - If `build` set: download source (curl), extract (tar), compile inside **bubblewrap** sandbox (isolated, no network, read-only /usr /lib /bin /nix)
   - Stage dir is populated with build output
   - Write `meta/snap.yaml` (arch-specific)
   - Copy stage contents into build root
   - Run `mksquashfs -comp xz -all-root` → `{name}_{version}_{arch}.snap`

## Design Decisions Captured

- ADR-0001: Data-description Lua (return-table contract, not scripting)
- ADR-0002: Lua DSL is schema source of truth (validation in Lua, Rust passive)
- ADR-0003: `shoot.lua` always returns table of named outputs (multi-output from day one)
- ADR-0004: Injected globals return values, not mutation
- Bubblewrap for build isolation (not chroot, not microsandbox, not Docker)
- `$STAGE` always absolute path (needed for autotools `DESTDIR`)
- Build dir mounted at `/build` inside sandbox (temp dir paths differ between host/guest)
