# Handoff: shoot — Reproducibility Pipeline

## Session Scope

Three sessions built a complete reproducibility pipeline on top of the 8-phase MVP (already committed before this session). The project went from "working CLI that builds snaps" to "reproducible build system with source pinning, snap pinning, image assembly, lockfile, package index, CI/CD, and doctor."

## What Was Done

See individual commits for full diff — this is a map, not a duplicate.

### Commit `b09a660` — Reproducibility foundation
- **Source pinning**: `source` accepts `{url, sha256}` table in DSL; SHA-256 verified after download
- **`SOURCE_DATE_EPOCH`**: env var propagated to `mksquashfs` for reproducible timestamps
- **Lockfile** (`shoot.lock`): auto-generated JSON capturing source hashes + snap pins
- **Snap store client** (`src/store.rs`): query API v2, download by revision, sha3-384 verify
- **`pin()` DSL**: declare pinned snaps by name + revision + sha3-384
- **`image()` DSL**: compose rootfs from multiple pinned snaps (base, kernel, gadget, apps)
- **Image assembly** (`src/image.rs`): resolve → download → verify → unsquashfs → merge kernel → bundle → pack SquashFS
- **`shoot image` CLI**: `--arch`, `--channel`, `--cache`, `--source-date-epoch`, `--lockfile`
- **CI/CD** (`.github/workflows/ci.yml`): GitHub Actions with devbox (build, test, clippy, fmt)
- **`devbox.json` scripts**: `build`, `test`, `clippy`, `fmt-check`, `check`
- **README**: updated with quickstart

### Commit `d8ce18a` — Package index
- **`src/index.rs`**: `PackageIndex` struct + JSON format
- **`shoot index` CLI**: `list`, `add <name>`, `resolve` (query store, pin all by arch)
- **`index()` DSL**: look up snaps from `package-index.json`, returns pinned refs
- **Default entries**: core22, pc-kernel, pi-gadget, lxd auto-populated

### Commit `cecff69` — Doctor
- **`src/doctor.rs`**: check mksquashfs, unsquashfs, curl, tar, bwrap, squashfs version
- **`shoot doctor`**: formatted report, exit 1 on missing deps

## Notable Design Decisions (not in ADRs)

- **`unsquashfs -f` is not "force"**: `-f` means something else in unsquashfs and breaks extraction. Use `-no-xattrs` instead to suppress device-node warnings.
- **Snap Store API `revision`**: is at the channel-map entry top level, NOT inside `channel` object. `channel` has `track`, `risk`, `architecture`.
- **Store channel format**: is `track/risk` (e.g. `latest/stable`), not just `channel.name`.
- **`SOURCE_DATE_EPOCH`**: mksquashfs 4.4+ reads it natively — no need to pass `-mkfs-time`. Just ensure the env var is inherited by the child process.
- **Lua `index()` function**: registered as a Rust closure in `lua.rs::new_lua()`, not defined in `init.lua`. Uses `SHOOT_ARCH` and `SHOOT_INDEX_PATH` env vars for context.

## Things Not Yet Done (candidate next work)

- **Pinned toolchain**: mount pinned gcc/make/libc in bubblewrap instead of host `/usr`. Currently binaries vary across machines. See `run_build_command()` in `snap.rs`.
- **Full disk images**: partition table + bootloader from gadget snap. `image.rs` currently produces a SquashFS rootfs, not a bootable `.img`.
- **Multi-output example**: a `shoot.lua` with >1 output + image declaration. Only single-output examples exist.
- **Cross-arch builds**: `--arch arm64` on amd64 host (needs QEMU or cross-toolchain).
- **Cache GC**: `~/.cache/shoot/snaps/` grows unboundedly with snap downloads.
- **Error polish**: better miette diagnostics for store API errors, unsquashfs failures, lockfile conflicts.
- **`STATE.md` + `ROADMAP.md` update**: both are stale from before implementation.
- **Documentation**: CLI usage docs beyond README, man page generator.
